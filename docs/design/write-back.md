# v0.4 安全写回设计（草案，未实现）

> 状态：设计文档。按维护策略，写回达到安全门槛之前不实现、不打包、不分发。
> 当前表格编辑是“仅内存”，退出/切换文件即丢弃（UI 已有未保存提示条）。

## 1. 目标与边界

### 目标
- 让用户能把“仅内存”的编辑安全地写回原配置文件；
- 写回前有完整备份、写回可撤销、失败不留半文件；
- 只允许格式模型能够 **无损往返（round-trip）** 的改动；
- 所有写操作都经过用户确认并留下可审计记录。

### 非目标（v0.4 不做）
- 不新增“结构化配置编辑器”级别的语法补全/校验；
- 不做多用户协同、权限代理服务；
- 不通过该功能放宽“系统目录只读”的安全立场；
- 不以 root 直接编辑 `/etc`（见 §5 提权策略）。

## 2. 威胁模型

写回面对的典型风险：
1. **格式破坏**：写入的序列化结果无法再被本程序或其他工具解析；
2. **语义破坏**：注释/顺序/引号风格被“规范化”丢失，或注释被当成配置写入；
3. **权限/所有权破坏**：写回后文件属主、权限、ACL、SELinux 标签变化；
4. **竞态（TOCTOU）**：读取后到写入前文件被他人修改，覆盖其改动；
5. **符号链接劫持**：目标路径是符号链接，写入落到了别处；
6. **半写文件**：进程中断导致文件截断/损坏；
7. **误改系统文件**：用户点错，破坏启动/服务配置。

## 3. 安全门槛（全部满足才允许“写回”菜单可用）

- [ ] 每种支持格式具备 **解析→序列化→再解析** 的往返测试（逐字节或语义等价）；
- [ ] 序列化保留：注释、空行、缩进、引号风格、顺序（除非用户显式删除）；
- [ ] 写前全量备份到 `$XDG_DATA_HOME/linux-regedit/backups/<file>.<ts>.bak`；
- [ ] 写后立即重新解析并 diff，不一致则自动回滚并报错；
- [ ] 原子写（临时文件 + `rename`），不直接 truncate 原文件；
- [ ] 目标路径拒绝：符号链接、`/proc`、`/sys`、`/dev` 等特殊文件系统；
- [ ] 写前检测文件 mtime/size/内容哈希变化，冲突则中止并提示；
- [ ] 全程有“仅此一次”的明确确认对话框（含备份路径与撤销说明）；
- [ ] 操作日志（谁/何时/哪文件/备份位置）。

## 4. 数据模型：把“内存行”变回“文件补丁”

### 当前状态
`LrConfigItem` 只保留键、值、节、注释、启用标志；行顺序保存在表格模型中，
但与原始文本的关系（引号、缩进、空行）已丢失。

### 建议模型
在解析阶段为每个文件保留 **原文行快照**，编辑表示为行级变更：
- `LrTextDoc`：`GArray<LrTextLine>`，每行含原始文本与分类
  （注释/空行/节头/键值对/其他）；
- 表格编辑不直接改文本，而是生成 `LrEditOp`：
  - `SET_VALUE {section, key, new_value, new_enabled}`
  - `RENAME_KEY {section, old, new}`
  - `ADD_ITEM` / `REMOVE_ITEM`
  - `CHANGE_COMMENT`
- “写回”= 把编辑操作应用到 `LrTextDoc` 行序列，尽量原地替换值部分、
  保留注释与排版；应用后必须能重新解析出同一份 `LrConfigItem` 集合。

只有解析器实现 `lr_doc_apply_edit()` 的格式才允许写回；未实现的格式保持只读。

## 4.1 格式保全：为什么不能“整文件重写”

整文件“解析→序列化”必然规范化注释、空行、引号风格与顺序，因此写回采用
**最小化、行锚定、补丁式**方案：

1. **原样保留层（source map）**：解析器除了产出 `LrConfigItem`，还记录每个
   逻辑项对应的原文行区间/字节区间与整行原文（缩进、引号、行内注释、续行
   `\` 等）。未编辑的行在写回时逐字回放，一个字节都不改。
2. **编辑层（语义操作 → 文本补丁）**：用户操作建模为 `LrEditOp`，每个格式
   driver 提供 `apply_edit()`：
   - `SET_VALUE`：只替换 `=` 右侧 value 区段，保留 key/缩进/引号/行内注释；
   - `ENABLE/DISABLE`：整行加/去注释前缀（`# `、`;`），其余不动；
   - `ADD_ITEM`：从相邻同节行“抄样式”生成新行；
   - `RENAME_KEY`：只替换 key token；
   - `REMOVE_ITEM`：删整行，或按策略改为注释掉。
   JSON/XML/apt 等非行级格式做节点区间定位，只重写被改区域；做不到的格式
   不开写回。
3. **校验门（round-trip gate）**：写盘前把新文本重新解析并与期望模型做语义
   diff；出现计划外的键/注释/顺序变化即中止。
4. **安全网**：备份 → 外部修改检测（mtime/哈希）→ 原子写（temp+rename，并复制
   owner/权限/xattr）→ 写后重解析校验 → 失败自动回滚 → 撤销入口。

## 4.2 分格式能力矩阵（建议点亮顺序）

| 格式 | 建议 | 保真难度 |
|---|---|---|
| 扁平 KV / INI / systemd / TOML | 首批开放：行级最小补丁 | 低-中 |
| keyword（sshd_config 等） | 整行替换参数 | 中 |
| apt | 块感知定位，保留 `{}` / `;` | 中高 |
| JSON / XML | 先只读；或“仅重写被改节点 + 保留缩进风格” | 高 |

## 4.3 保真细节清单（写回测试必须覆盖）

- 行尾 LF/CRLF、编码、BOM、末尾是否有换行；
- 注释样式与语义：`#`/`;`/`//`、`##` vs `# x=y`（nanorc 惯例）、行内注释；
- 引号风格与是否留空格、值内 `#`；
- 空行、缩进、键的顺序（除非用户显式排序）；
- 文件属主、权限、ACL/SELinux 标签（原子 rename 会换 inode，需复制 stat/xattr）；
- 符号链接目标解析与特殊文件系统拒绝。

## 5. 权限与提权

### 用户自有文件（`~/.config`、家目录）
- 直接原子写，无需提权；
- 若文件属主非当前用户 → 进入“需要提权”流程。

### 系统文件（`/etc`、`/boot` 等 root 属主）
- **默认拒绝**；
- 提供两条可选路径（实现前再决策，均可配置/可关闭）：
  a. **Polkit 规则**：弹系统授权对话框，仅执行“写临时文件→校验→原子替换”；
  b. **外部 helper（pkexec/sudo）**：helper 做最小操作并受路径白名单约束。
- 禁止直接以 root 长期运行 GUI；
- helper 只接受“目标绝对路径 + 已签名/已验证的新文件”，不接受任意 shell 命令。

### M2c 落地条件与 helper 契约（待 polkit 环境验证）

当前开发容器没有 polkit/pkexec，以下契约先写死、待有环境后做端到端验证：
- 安装 `linux-regedit-save-helper`（root 可执行）与 polkit action
  `org.linux-regedit.app.save`（`auth_admin_keep`）；
- UI 检测目标不可写 → 生成候选文本与原文 SHA-256 → 经 `pkexec` 调 helper；
- helper 输入协议：stdin 第一行 `LR-SAVE-V1 <sha256hex>`，随后为候选全文；
- helper 校验：绝对路径、非符号链接、realpath 一致、磁盘原文哈希与期望一致、
  候选大小/二进制限制，然后备份到 `/var/backups/linux-regedit` 并原子替换
  （保留属主/权限）；
- 语义门（round-trip）只由 GUI 侧执行；helper 不做“解释格式”的事，职责最小化。

## 6. 写回流程（伪代码）

```
user clicks Save (仅当 §3 门槛全绿)
  ├─ 1. 备份原文件（含哈希）            → backups/
  ├─ 2. 重新读取磁盘文件，与打开时快照对比
  │     └─ 不一致 → 中止，提示“文件已被外部修改”
  ├─ 3. 应用编辑操作到 LrTextDoc
  ├─ 4. 序列化为新内容（保留注释/排版）
  ├─ 5. 重新解析新内容并 diff 模型
  │     └─ 不一致 → 中止，不落盘
  ├─ 6. 写临时文件（同目录、0600）→ fsync
  ├─ 7. 原子 rename 覆盖原文件
  ├─ 8. 再解析落盘结果并校验
  │     └─ 失败 → 用备份自动回滚 + 报错
  └─ 9. 记录操作日志，清除 dirty 状态
```
